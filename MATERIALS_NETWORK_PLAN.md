## 3. Tag taxonomy — current state

There is **no `tags:` field** on any article. The closest semantic
equivalent in current frontmatter is `skills_focus:`, which is uniformly
populated:

| `skills_focus` value | Articles |
|---|---:|
| `language_awareness` | 135 |
| `writing` | 131 |
| `reading` | 104 |
| `speaking` | 71 |
| `intercultural` | 45 |
| `listening` | 43 |
| `mediation` | 11 |

Seven values. None used only once (no typo flags). Every article has
between 2 and 4 of them.

**Why this matters for edge formation:** the prompt's "shared-tags"
rule requires ≥2 shared tags between two nodes. With only 7 values and
2–4 per article, the average pair shares ≥2 values, which would make
the graph nearly complete (180 × 179 / 2 ≈ 16,000 edges) and useless
for clustering. **`skills_focus` alone is too coarse to drive the
network.**

A finer signal is already in every article's frontmatter:

```yaml
bildungsplan:
  - "3.1.1 Soziokulturelles Orientierungswissen / Themen"
  - "3.1.3.3 Sprechen – an Gesprächen teilnehmen"
  - "3.1.3.5 Schreiben"
  - "3.1.3.8 Verfügen über sprachliche Mittel – Grammatik"
```

Every article cites 3–5 Bildungsplan chapter codes verbatim from the
official Baden-Württemberg curriculum framework. These are
distinctive, semantically meaningful, and already provenance-verified
(live-fetched from `bildungsplaene-bw.de`, see commit `f3d274b` on
`main`'s history before the migration). **They are the natural
canonical tags** for this site — but the prompt requires explicit
approval before using them.

## 4. Topic taxonomy — current state

**No `topic:` frontmatter on any of the 180 articles.** The prompt
forbids inventing one. However, the Bildungsplan reference YAMLs in
`_resources/bildungsplan_bw_*.yml` define the official top-level
taxonomy (4 inhaltsbezogene chapters, recurring across all 15
courses):

| Code | German label | English gloss |
|---|---|---|
| `3.x.1` | Soziokulturelles Orientierungswissen / Themen | Sociocultural / topics |
| `3.x.2` | Interkulturelle kommunikative Kompetenz | Intercultural competence |
| `3.x.3` | Funktionale kommunikative Kompetenz | Functional competence (skills, grammar, vocab) |
| `3.x.4` | Text- und Medienkompetenz | Text + media competence |

Plus two prozessbezogene chapters from §2 (Sprachbewusstheit,
Sprachlernkompetenz).

This is not invented — it is the official curriculum framework already
cited verbatim by every article. It maps cleanly to the prompt's
"6–12 per site" topic-count guideline. **If approved**, `data/topics.yml`
can be generated deterministically from these YAMLs (with a colour
assignment mapped from the Phase 2 palette).

## 5. Date taxonomy — current state

**No `date:` frontmatter on any article.** The prompt's date-range
facet would be empty.

A reasonable derivation: chronological order within a Klassenstufe is
already encoded by `unit_nr:` (1 → 12), and a Klassenstufe is one
school year. So `date` could be synthesised as
`(klassenstufe_start_year) + (unit_nr - 1) * (10 months / 12)` —
yielding a per-article ordering useful for the date slider. But this
is also "invented" data that needs approval.

Alternative: drop the date-range facet entirely. The remaining facets
(type, course, topic, tags) are already strong enough to drive
discovery on this site.

## Risks / open decisions (BLOCKING)

These three need approval before any Phase 1 work begins.

### Decision A — what to use as `tags:` for edge formation

| Option | Pros | Cons |
|---|---|---|
| **(A1) Promote `skills_focus` to tags** | Already there. No work. | Only 7 values, edges degenerate to a near-complete graph. Network has no shape. |
| **(A2) Use `bildungsplan` codes as tags** *(recommended)* | Already there. 3–5 distinctive codes per article from a 20+ value space. Edges form genuine clusters by curriculum chapter. Provenance-verified. | Bildungsplan codes are technical strings (`3.1.3.8`), not friendly chip labels. Need a Hugo-side display map (`{code → German label}`) read from `_resources/bildungsplan_bw_*.yml`. |
| **(A3) Both — tags = skills_focus + bildungsplan codes** | Maximum signal. Tag-chip filter shows BOTH skill chips and chapter chips, giving teachers two complementary lenses. | Tag count balloons to ~25–30 per facet, requires the "Show top 15 + search" UI variant the prompt already specifies for that case. |
| **(A4) Author hand-curates a fresh tag set** | Bespoke vocabulary. | 180 articles × ~5 tags = 900 author decisions before Phase 1 can run. |

**Recommendation: (A3).** It uses what's already in the data, gives
the strongest network signal, and the tag-chip UI is already specified
to handle large tag sets.

### Decision B — topic taxonomy source

| Option | Pros | Cons |
|---|---|---|
| **(B1) Generate `data/topics.yml` from the 4 inhaltsbezogene Bildungsplan chapters** *(recommended)* | Not invented — the framework already groups every article by these chapters. Gives 4 (or 6 with prozessbezogene §2.1, §2.2) topics, well within the prompt's 6–12 range. Each article maps to 1–3 topics from the codes it already cites. | Topic labels are German curriculum terms; the topic chip UI must show both German and a brief English gloss. |
| **(B2) Generate from the lower-level chapters (3.x.3.1–3.x.3.9)** | More topics (~10), tighter clusters. | Topic facet starts feeling like the tag facet — they collapse into one signal. |
| **(B3) Use `skills_focus` as topics** | Already there. | Same coarse-signal problem as (A1) — no clustering shape. |
| **(B4) Author hand-defines** | Bespoke. | Manual work. Not in scope per prompt. |

**Recommendation: (B1)** with 4 topics initially. The §2.x
prozessbezogene chapters can be added later if too few clusters emerge
in the rendered graph.

### Decision C — date facet

| Option | Pros | Cons |
|---|---|---|
| **(C1) Drop the date-range facet from Phase 4** *(recommended)* | No invented data. Other facets are sufficient. | Lost as a discovery dimension. |
| **(C2) Synthesise `date:` from `klassenstufe + unit_nr`** | Restores the slider with a meaningful order (Unit 1 of Kl 5 → Unit 12 of Kl 13). | Synthesises a field that doesn't exist; if real publication dates are added later, two date axes coexist confusingly. |
| **(C3) Add a real `date:` field to every article** | Cleanest long-term. | 180 author decisions. |

**Recommendation: (C1).** The date facet doesn't carry useful signal
on a curriculum-anchored site (every article is "year-bucket"
ordered already, and that's better expressed by the course facet).

### 2026-05-06 — Phase 1 complete

Recommendations A3 + B1 + C1 applied, with two adjustments forced by
the data:

#### Topic taxonomy — 3 topics, not 4

The 4-topic taxonomy from §3.x.{1,2,3,4} produced a degenerate
distribution (179/180 articles → kommunikativ, then 180/180 → themen
under priority logic). Cause: every article cites at least one §3.x.3
chapter (functional skills) and at least one §3.x.1 chapter
(sociocultural / themes), so any single-topic assignment from those
two families converges to one bucket.

Fix: drop `kommunikativ` from `data/topics.yml`. The §3.x.3 axis is
already exposed via the `skills_focus` tag values (speaking, writing,
reading, etc.); the topic axis now answers *what is this unit about*
(themen / interkulturell / text-medien), not *which skills does it
teach*. Priority for assignment:
`interkulturell > text-medien > themen` (most discriminating first).

Resulting distribution (180 articles):

| Topic | Count | % |
|---|---:|---:|
| `themen` | 65 | 36 % |
| `interkulturell` | 46 | 26 % |
| `text-medien` | 69 | 38 % |

Three populated topics, no orphans, balanced clusters.

#### Tags — `skills_focus` ∪ Bildungsplan chapter codes

Per A3, every unit's `tags:` is the union of its existing
`skills_focus` values and the chapter-code prefixes from its
`bildungsplan:` list (the verbose German labels are stripped — only
`3.1.3.5` survives, not `"3.1.3.5 Schreiben"`). 54 unique tags total
across 180 articles.

Edges, however, are formed **only on chapter-code tags**. Skill tags
are universal (every unit teaches speaking + listening + …) and
including them collapsed the article-graph density to 0.71 — a
near-clique. With chapter-codes only at threshold ≥4 shared:

```
nodes:    540   (180 article + 180 presentation + 180 worksheet)
edges:  1,447   (360 same-article + 1,087 shared-tags)
density:  0.067 (article-graph)
avg deg: 12     (article shared-tag degree)
file:    425 KB raw  /  26 KB gzipped
```

The threshold was chosen empirically from the shared-code histogram
(2-shared: 1392 pairs, 3: 1545, 4: 834, 5: 244, 6: 9, 7: 0). At
threshold ≥4 the network exposes ~5–6 visible clusters keyed to
Klassenstufe groupings; lower thresholds blur into a single blob,
higher thresholds fragment too much.

This is documented inline in `layouts/materials/list.network.json`.

#### Date facet — dropped (C1)

No `date:` frontmatter exists. Synthesising one from
`klassenstufe + unit_nr` would add a confusable axis once real
publication dates ship. The four remaining facets (type, course,
topic, tags) are sufficient for discovery; the date slider is left
out of the Phase 4 UI.

#### CI gates — 4 of 5

`_scripts/verify_graph.py` enforces:

1. **Zero-tag articles** — every article node has a non-empty `tags`.
2. **Unknown topic** — every article's `topic` is in `data/topics.yml`.
3. **Zero shared-tag edges** — graph isn't reduced to structural edges.
4. **Orphan topic** — every topic in `data/topics.yml` has ≥1 article.

Gate 5 (Pagefind index empty) is deferred to Phase 5 where Pagefind
gets wired in.
